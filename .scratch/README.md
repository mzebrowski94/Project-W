# Tickets

The project's issue tracker: one folder per feature or review, one markdown file per ticket, with
`Status:` lines and blocking links. Agents read and update it with the tools they already have - the
conventions are in [`docs/agents/issue-tracker.md`](../docs/agents/issue-tracker.md).

Kept as a record of how work was specified, split and handed to agents, including the unattended runs.
It is working material, not maintained documentation: a closed ticket is not updated when the code moves
on. What was decided lives in [`docs/adr/`](../docs/adr/README.md) and
[`docs/design/decisions/`](../docs/design/decisions/README.md).
