# AI playbook - What I learned building project with AI agents

**Most of these practices are worth carrying into future projects; a few are specific to building a video game.**

This file is for people. Agents working in the repository start at [`CLAUDE.md`](../CLAUDE.md) and do
not need it.

The arrangement throughout: an agent (Claude Code) writes most of the code, one person decides, reviews
and plays. Nearly every practice below exists because of that - it either saves the reviewer's attention
or replaces a memory the agent does not have.

## Context: what the agent knows

| Practice | How it works here | What it buys |
|---|---|---|
| **A thin always-on file** | [`CLAUDE.md`](../CLAUDE.md) holds only what applies to every change: scope rules, the done checklist, the design pillars, the module map. | Rules that are always loaded are always paid for. Keeping the file short keeps the important lines from drowning. |
| **On-demand docs behind a "read it when" table** | Fourteen documents - conventions, performance, determinism, simulation order and so on - each with the trigger that should open it. | The agent reads the performance rules when it writes a hot loop, not when it renames a field. |
| **Pillars inline, invariants on demand** | Seven design pillars sit in the always-on file by decision. The detailed [invariants](design/README.md) are split one file per domain, each row marked `enforced`, `judgement` or `deferred`. | A contradiction usually slips in during a session nobody framed as design work - exactly when an on-demand file would not be read. |
| **A glossary as the reuse check** | [`docs/glossary.md`](glossary.md) has one word per concept, and a new domain word must be added before it is used. `CLAUDE.md` lists the existing building blocks under "reuse before you create". | If the word exists, the thing usually does too. It is the cheapest guard against an agent building a second way to do what already has one. |
| **Decision records with "Do not build"** | [ADRs](adr/README.md) for structure and [G-records](design/decisions/README.md) for gameplay share one format: trigger, constraint, what enforces it, rejected alternatives. | An agent starts every session without memory. The rejected alternatives stop it re-proposing last month's dead end. |
| **"Enforced by" on every record** | Each record names the test that fails if it is broken, or says plainly that nothing mechanical does. | A rule nothing enforces needs more attention, not less - and now I know which rules those are. |
| **Docs are pruned, and tests police them** | Expired plans are deleted. [`SourceCitationsTest`](../core/src/test/java/pl/mzebrows/pwt/client/SourceCitationsTest.java) and [`DecisionRecordsTest`](../core/src/test/java/pl/mzebrows/pwt/client/DecisionRecordsTest.java) fail the build on a citation of a missing doc or an invariants file left empty. | Documentation an agent trusts must not be allowed to rot. A stale doc is worse than none. |
| **Comments hold the contract, records hold the history** | A comment says what the code promises, what must stay true, and which record decided it. Why it changed, the bug behind it and the alternatives turned down go to the decision record and git ([`docs/conventions.md`](conventions.md#clean-code)). | Every comment is re-read in every session that opens the file. History there costs tokens forever and goes stale first. |
| **Docs written for the reader they have** | Agent-facing docs state constraints and intent, never how a system behaves - "that is what the code is for". | A description that disagrees with the code misleads an agent more than a missing one. |

## Enforcement: rules the build checks

| Practice | How it works here | What it buys |
|---|---|---|
| **One verify command everywhere** | [`.claude/scripts/verify.sh`](../.claude/scripts/verify.sh) formats, compiles, lints and tests, identically on the desktop, in a sandbox and in the cloud. | "Done" has one definition, and the agent can check it itself. |
| **A verification ladder** | Five levels from "one test" to "play it" in [`docs/workflow.md`](workflow.md#verification-ladder): start at the cheapest that can refute the change, escalate on a trigger. | Fast iteration without ever claiming done below a full green run. |
| **Architecture tests per module** | Five [ArchUnit](../sim/src/test/java/pl/mzebrows/pwt/sim/ArchitectureTest.java) suites: `sim` may not touch rendering, the wall clock, unseeded randomness or hash order; `net` may not see libGDX; `ui` may not write a component. | Module boundaries are the first thing to erode when code is cheap to write. These cannot. |
| **Fenced packages** | Systems live in packages by domain, package-private by default, meeting only through declared ports ([ADR 0020](adr/0020-systems-live-in-fenced-packages-by-domain.md), [0021](adr/0021-the-client-lives-in-fenced-packages-by-layer.md)). | The agent's "read narrow" rule becomes safe: what a package does not export cannot be depended on. |
| **A guard is trusted once it has failed** | Every architecture rule was watched failing against a deliberate violation before it was kept; a new one is not finished until someone has seen it fail. | A rule that can never fail looks exactly like a rule that holds. |
| **Banned APIs, each with what catches it** | One table in [`docs/conventions.md`](conventions.md#banned-and-what-to-use-instead): what is banned, what to use instead, where, and which test catches it - or "nothing". A row is added when a mistake happens twice, not when it is imagined once. | The agent gets the alternative together with the ban, and the "nothing" cells show where review still has to look. |
| **Docs checked against the code** | [`docs/components.md`](components.md) says which systems write each component, and a test reads the compiled classes and fails if the table and the code disagree ([ADR 0019](adr/0019-a-component-names-its-writers.md)). The [UI spec](ui/menu_layout_agent.md) gives every page an id; [`UiSpecTest`](../ui/src/test/java/pl/mzebrows/pwt/ui/page/UiSpecTest.java) fails if a spec id has no code or the code has no spec row. | Documentation that is verified is documentation the agent can rely on. |
| **Static analysis with warnings as errors** | Spotless, Error Prone, NullAway in JSpecify mode, `-Xlint:all -Werror` ([ADR 0005](adr/0005-quality-tooling.md)). | Whole classes of mistake are caught mechanically, and formatting never appears in a review. |
| **Determinism as a test asset** | Same seed and inputs give the same world. [`SimulationDeterminismTest`](../sim/src/test/java/pl/mzebrows/pwt/sim/SimulationDeterminismTest.java) replays every scenario twice; an opt-in fuzz test feeds random input; a desync report diffs two world dumps field by field. | Any bug can be reproduced, which is the difference between an agent diagnosing and an agent guessing. |
| **Whole sessions in one test** | [`SessionHarness`](../net/src/test/java/pl/mzebrows/pwt/net/session/SessionHarness.java) runs a host and peers over an in-memory network with lag, packet loss, drop-in and a desync healed. | Networking is tested without sockets, sleeps or a second machine. |
| **Config as data, checked both ways** | Every tunable lives in a `.properties` file bound to a record. A key with no record, or a record field with no key, fails the build. | No magic numbers, no orphan keys, and I can tune the feel without touching code. |
| **Kinds as data** | A new enemy, weapon or upgrade is an enum constant, a definition and a block of config - never a new class or branch (G0008). The [`new-kind`](../.claude/skills/new-kind/SKILL.md) skill has the steps. | Content grows without the code growing, and the agent has no room to invent a parallel mechanism. |
| **Tests that cover content automatically** | [`ScenariosTest`](../sim/src/test/java/pl/mzebrows/pwt/sim/scenario/ScenariosTest.java) applies to every registered scenario: it must describe itself, spawn one commander and survive 300 ticks. | New content is tested the moment it is registered, with nothing to remember. |
| **A performance guard** | An opt-in benchmark measures time and allocation per step from 100 to 800 units; the done checklist bans allocation in per-entity loops. | Hot-path regressions are a number, not an impression. |

## Workflow: how a session runs
Sessions driven by [Matt Pocock's](https://github.com/mattpocock/skills) and project specific skills.

| Practice | How it works here | What it buys |
|---|---|---|
| **Agree, then plan, then write** | Non-trivial work starts with questions about what the request leaves open, then a plan I approve. Small, well-specified changes just get done. | The expensive misunderstandings surface before any code exists. |
| **Grilling before building** | A design is interrogated question by question, each with the agent's recommended answer, until nothing is silently assumed. Outcomes become decision records. | I answer "yes" or correct a recommendation instead of writing a specification from scratch. |
| **Tests first, in three steps** | Broad tests of what the logic should do; the implementation; then back to the tests for the specific cases found while implementing. | Specifics discovered while implementing beat specifics guessed beforehand. |
| **Tests that read well when they fail** | JUnit 5, AssertJ for every assertion, Mockito only at real boundaries. A test is named for the behaviour, so a failure reads as a sentence (`movesAnEntityByItsVelocityEachStep`); collections are asserted through `extracting`, so a failure prints values rather than `PooledEntity@1a2b`; floats always with an explicit tolerance. The [`unit-tests`](../.claude/skills/unit-tests/SKILL.md) skill points at four model tests, which outrank its written rules. | The failure message is the agent's first clue. When it names the behaviour and the wrong value, the next step is a diagnosis, not a debugging session. |
| **A test that needs a mock points at the design** | `sim` has no I/O, clock or services, so a test there that seems to need a mock is reported as a design problem. In the client, deciding is split from drawing: decisions take plain values and are tested, drawing stays thin and is checked by playing. | Testability goes into the design, instead of into scaffolding built around it. |
| **A failure protocol** | Read the actual error; check the table of known failures; state the cause in one sentence before editing; one hypothesis per attempt; two failed fixes and stop. | It ends the loop where an agent keeps trying things. A fix chosen before the cause is named is a guess. |
| **A failure-mode table** | Every failure actually hit is a row in [`docs/workflow.md`](workflow.md#failure-modes): symptom, real cause, action. Rows that stop happening are deleted. | Most of what goes wrong has gone wrong before, and the known cause is usually not what the message suggests. |
| **A yes/no done checklist** | Fourteen lines in `CLAUDE.md`, each one checkable by the agent itself. "A no is not done." | Quality criteria that can be verified beat ones that can only be aspired to. |
| **The smallest coherent patch** | Touch what the task names. If it needs a larger structural change: stop, name the dependency chain, wait. The simple version comes first; a general, reusable one only when a second place that needs it already exists. | Diffs stay reviewable by one person, and abstractions appear when they are needed, not in advance. |
| **Scripts for mechanical changes** | Large repetitive edits run through small scripts instead of file-by-file edits: [`move-classes.py`](../.claude/scripts/move-classes.py) moves classes and fixes every reference, [`system-graph.py`](../.claude/scripts/system-graph.py) tests a proposed package split before anything moves, [`component-index.py`](../.claude/scripts/component-index.py) regenerates the component index. | A move across ninety files becomes one command to review instead of ninety chances to slip - and costs a fraction of the tokens. |
| **A contract for the final message** | The fewest words that carry the information, and always what the diff cannot show: the cause diagnosed, decisions the agent took, the tuning keys added, a suggested commit message. | I review faster, and I know which numbers to play with after a gameplay change. |
| **A fresh-session prompt** | At a natural stopping point the agent says whether the next step would go better in a new session, and writes the standalone prompt to start it. | Long contexts degrade. The handover is written by the one who knows what matters. |
| **Skills in two layers** | [Project skills](../.claude/skills/) (`feature`, `new-system`, `new-kind`, `new-biome`, `unit-tests`, `perf-audit`, `game-patterns`) carry the local rules. Matt Pocock's engineering skills drive the session; [three small files](agents/) point them at this repository's tracker, labels and glossary. | Procedures are reusable and versioned, and proven general-purpose skills are adopted rather than reinvented. |
| **Tickets as local markdown** | Specs and issues live under `.scratch/<feature>/`, one file per ticket, with status lines and blocking links. | The agent reads and updates the tracker with the tools it already has. |
| **Scenarios and a proving ground for feel** | Each system gets an arena built to make it visible; the proving ground lets me fight any enemy with any setup. | No test covers feel. The agent builds; I play and judge. |
| **Scaffolding is listed** | A stand-in is allowed only while it is named in [`alpha-phase.md`](design/alpha-phase.md), with what replaces it. | Temporary solutions stay visible and never pass for design. |
| **A backlog with triggers** | Deferred work in [`docs/backlog.md`](backlog.md) records why it waited and what should bring it back. | A deferral is a decision, not a forgotten TODO - and the agent checks it before proposing a refactor. |
| **Periodic AI module reviews** | A whole module is reviewed with one reusable prompt, [`/module-review`](../.claude/commands/module-review.md), whose checks are the defects the first review actually found; findings become backlog entries or tickets. | Slow drift gets caught even though each individual diff looked fine. |
| **A friction log** | Anything a change on my side would fix - a permission, an allowlist entry - is named in one line when hit, and collected. | The harness improves in the places it actually hurts. |
| **Guarded autonomy** | In the cloud, one script may commit and push, only to the agent's own branch. In unattended runs, agents work in separate worktrees; a git hook refuses any move of `main`, another refuses push and destructive commands. | The agent gets enough freedom to work alone, and the blast radius is set by mechanism rather than by instruction. |
| **Parallel agents, planned like a team** | Before fanning out, the orchestrator hands each ticket its own block of decision-record numbers; exploration and merging run on a cheaper model, implementation on the main one; each agent edits by absolute path inside its own worktree ([`docs/workflow.md`](workflow.md#afk-runs)). | Colliding ids and cross-worktree edits are designed out, and the strongest model is spent on the work that gets judged. |
| **Provisional decisions** | In an unattended run the orchestrator settles open questions itself, marks each *provisional, for review*, and lists them with their alternatives. A question that would break a design pillar is left open. | Work continues without me, and nothing is decided behind my back. |

## How it evolved

| When | What changed |
|---|---|
| 7 Sep 2026 | Project scaffolding and AI configuration in the first commit: `CLAUDE.md` with "agree, then plan", the verify script, quality tooling, the first ADRs, a failure-mode table. The same day, the alpha phase: systems built to be built on, each judged in a scenario of its own. |
| 12 Sep | The rulebook takes shape: "read narrow", "reuse before you create", a yes/no done checklist, tests first in three steps, "Do not build" on every record, and the rule that a guard is trusted only after it has been seen failing. Docs and skills checked against the sources; the glossary grouped by subsystem; a generated component index. |
| 18 Sep | A rule against building ahead: the agent writes the simple version of what a task needs, and the general, reusable one only when a second place that needs it already exists. |
| 24 Sep | Online play decided on paper first - decision records, a draft pillar, glossary - then built: a transport port, an in-memory test network, lockstep sessions. |
| 26 Sep | Cloud sessions: a session-start hook that provisions the toolchain, and a guarded commit script for the agent's own branches. |
| 26-27 Sep | The first AI review of a whole module, with its findings turned into tests rather than notes: system order held in `SystemOrderTest`, config bound from the shipped file with the literal defaults deleted, comments cut to contract plus a link. What waited went into a backlog with "bring it back when" triggers. |
| 30 Sep | Matt Pocock's skills adopted; the workflow split by environment; a contract for the agent's final message; the fresh-session prompt. Expired plan docs deleted, with a test that refuses any citation of them; every decision record given a status line and a consistency test; invariants split one file per domain. |
| 3 Oct | Structure made checkable: every component names its writers; the system graph measured with a script before the code moved into fenced packages; the `new-kind` skill. |
| 4-5 Oct | Missions designed before they were built: a map of tickets, then eight gameplay records settled one per question (G0062-G0069), a throwaway prototype for biome ground and a sketch of the `new-biome` skill, then the code in stages. |
| 11-12 Nov | Full agent (AFK) runs: playtest feedback charted as a map of tickets, agents in worktrees, git guards protecting `main`. |
