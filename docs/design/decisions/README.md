# Gameplay decisions

Closed decisions about what the game *is*, kept separate from `docs/adr/`, which covers technical
and structural choices. Same format, same discipline, different subject.

Open a record only when you are about to work against it or propose changing it - each one opens with
its **Status**, then a **Trigger** line saying when that is. The **Do not build** column is the negative index: if the
mechanic you are about to write appears there, it has already been rejected and the record says why. The Status column says whether a record still
holds - `docs/adr/README.md`, *Status*.

## When to write one

Only when an alternative was actually rejected **and is likely to be proposed again**. A decision
that nobody would argue with is an invariant - put it in `docs/design/invariants/` instead. A
description of how something works is neither; that is the code's job.

The fields, the status and how an old record is amended are the ADRs': `docs/adr/README.md`, *Writing
one here* and *Status*. Add the rejected names to the table above, so the negative index stays complete
without anyone opening a file.
